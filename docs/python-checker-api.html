Python answer tests

Basis questions, matrix conditions and your own checker

A question may have many mathematically correct answers. This guide helps you choose a test for a space or property and shows how ordinary STACK response trees (PRTs) continue to award the marks. The worked questions let you try each choice.

For teachers

Choose the mathematical test

Task Test What counts as correct
Give this particular matrix AlgEquiv Corresponding entries are equivalent and dimensions agree.
Give any basis of a matrix’s null, column or row space IsBasis Independent vectors span that space, regardless of the particular basis chosen.
Give any basis of a space specified by basis vectors IsBasis Independent vectors have the same span as the reference vectors.
Give a matrix satisfying the built-in conditions MatrixProperty Integer entries, a stated determinant or identity status.
Give a matrix satisfying another condition PythonChecker A named author function checks the stated property, such as positive definiteness.

AlgEquiv is an existing STACK answer-test name. IsBasis, MatrixProperty and PythonChecker are Python additions to this port. They keep STACK-style inputs and PRT scoring, but a native Moodle STACK question needs equivalent Maxima tests and may need different matrix-input settings.

Basis questions: use the matrix in the question

If the prompt asks for a basis of \(\ker A\), the PRT compares the learner’s proposed vectors against the original matrix \(A\), not against one precomputed list of basis vectors. Choose nullspace; use columnspace or rowspace for the other two spaces. The input’s model answer can be generated from \(A\) with the matching author helper. Another independent basis is still correct. For example, if \(A=\begin{pmatrix}1&2&3\\2&4&6\end{pmatrix}\), both the columns of \(\begin{pmatrix}-2&-3\\1&0\\0&1\end{pmatrix}\) and those of \(\begin{pmatrix}-5&-1\\1&-1\\1&1\end{pmatrix}\) span \(\ker A\).

IsBasis option Space being checked How learners enter vectors
nullspace Null space of the original \(A\) One vector per column
columnspace Column space of the original \(A\) One vector per column
rowspace Row space of the original \(A\) One vector per row
columns (default) Span of independent reference columns supplied by the author One vector per column
rows Span of independent reference rows supplied by the author One vector per row

The older columns and rows modes answer a different question: they compare spans with a supplied reference basis. Use them when that basis really defines the space in the prompt. For a matrix-defined space, use the original-matrix options above. The basis examples show alternate correct responses and learner-selected column counts. The matrix editor cannot represent an empty basis, so choose a task with a nonzero-dimensional answer space.

After checking a basis, green marks a nonzero vector in the target space when the valid submitted vectors are independent; it can still belong to an incomplete family. Yellow marks a dependent valid family and red marks zero or out-of-space vectors. These colors explain the answer; the PRT awards marks only for the complete basis in the examples. Edits and resizing clear the colors.

Matrix conditions and partial credit

The determinant-one task accepts any integer \(2\times2\) matrix with determinant \(1\) except the identity. Three PRTs give one third of the score each: integer entries, determinant and nonidentity. An entry-by-entry comparison with the model would reject other correct matrices.

MatrixProperty option Expected result supplied in PRT tans Condition
integer_entries true or false Are all entries integers?
determinant An exact rational value such as 1 Does this square matrix have that determinant?
identity true or false Is it the identity matrix?

The PRT’s tans is the expected property result, not the matrix in the prompt. For determinant one it is 1; for nonidentity it is false. MatrixProperty covers these three conditions only. A different condition calls for PythonChecker or an equivalent native STACK author calculation.

Positive definite matrices

The two activities distinguish a matrix’s structure from its positivity. For real matrices, the structural condition is symmetry \(A=A^T\). For complex matrices it is Hermitian symmetry \(A=A^*\), where \(A^*=\overline A^{\,T}\) conjugates the entries as well as transposing. These are one condition on different number domains: \(A^*=A^T\) for real entries.

The independent positivity test asks whether \(\operatorname{Re}(z^*Az)>0\) for every nonzero complex vector \(z\). It can hold even for a non-Hermitian matrix. Let \(H=(A+A^*)/2\). Then \(\operatorname{Re}(z^*Az)=z^*Hz\), so Sylvester’s criterion tests positivity exactly by requiring every leading principal determinant of \(H\) to be positive. In the real case, this is \(x^TAx>0\) and \(H=(A+A^T)/2\). For \(A=\begin{pmatrix}a&b\\c&d\end{pmatrix}\) with real entries, the test is \(a>0\) and \(ad-((b+c)/2)^2>0\), while symmetry separately requires \(b=c\).

The first activity requires both properties, the usual positive definite condition for a Hermitian matrix (symmetric in the real case). The second gives half the marks for each independently. Four real \(2\times2\) examples show why the scoring choice matters:

Matrix Hermitian (symmetric here)? Positive definite? Combined / separate marks
\(\begin{pmatrix}2&1\\1&2\end{pmatrix}\) Yes Yes \(1\) / \(1\)
\(\begin{pmatrix}2&1\\0&2\end{pmatrix}\) No Yes \(0\) / \(1/2\)
\(\begin{pmatrix}1&2\\2&1\end{pmatrix}\) Yes No \(0\) / \(1/2\)
\(\begin{pmatrix}0&1\\0&0\end{pmatrix}\) No No \(0\) / \(0\)

Both activities accept integers and exact fractions in the real and imaginary parts; enter %i for \(i\). Try matrix([2,%i],[-%i,2]): it is Hermitian and positive definite, with leading determinants \(2\) and \(3\). By contrast, matrix([1,%i],[%i,1]) is not Hermitian but does satisfy the independent positivity test because its Hermitian part is the identity. This is why checking \(A^T=A\) would give the wrong answer for complex entries.

Both activities use the same author Python file. The first uses the combined is_hpd function for one true/false decision; its single PRT awards full credit only when both conditions hold. Try the identity, the complex example above, and a matrix that has only one property. The authoring walkthrough shows the file, XML and Quarto block.

Give any real symmetric or complex Hermitian positive definite \(2\times2\) matrix. Use integers or exact fractions for real and imaginary parts; enter %i for \(i\).

The second activity checks Hermitian symmetry and positivity separately. It uses is_hermitian and is_positive_definite in two PRTs, each worth half the total. A non-Hermitian matrix that passes positivity earns only the positivity half; a Hermitian indefinite matrix earns only the symmetry half. Separate PRTs are useful when each condition should have its own marks and feedback. For an all-or-nothing task, use the combined checker or gate the positivity test behind a successful symmetry branch.

Author the positive-definiteness checker

Save this complete file as questions/spd-checker.py. It registers three functions. is_hermitian and is_positive_definite are independent tests; is_hpd combines them. The same exact test handles real and complex entries. Positivity is decided from the leading principal determinants of the Hermitian part, including for a non-Hermitian submission:

"""Check Hermitian symmetry and positivity for exact real or complex matrices."""


def hermitian(A):
    return A.rows == A.cols and A == A.H


def positive_definite(A):
    if A.rows != A.cols:
        return False
    # Re(z.H*A*z) equals z.H*H*z for real or complex matrices.
    H = (A + A.H) / 2
    return all(H[:k, :k].det() > 0 for k in range(1, H.rows + 1))


def check_property(ansm, expected, property_test, explanation):
    if any(part.is_Rational is not True
           for entry in ansm for part in entry.as_real_imag()):
        return {"valid": False, "correct": False,
                "feedback": "Use integers or exact fractions for the real and imaginary parts."}
    correct = bool(property_test(ansm)) == bool(expected)
    return {"valid": True, "correct": correct,
            "feedback": "" if correct else explanation}


def is_hermitian(ansm, expected):
    return check_property(ansm, expected, hermitian,
                          "The Hermitian-symmetry condition does not match the expected result.")


def is_positive_definite(ansm, expected):
    return check_property(ansm, expected, positive_definite,
                          "The positive-definiteness condition does not match the expected result.")


def is_hpd(ansm, expected):
    return check_property(ansm, expected,
                          lambda A: hermitian(A) and positive_definite(A),
                          "The Hermitian-positive-definiteness condition does not match the expected result.")


CHECKERS = {"is_hermitian": is_hermitian,
            "is_positive_definite": is_positive_definite,
            "is_hpd": is_hpd}

Each registered function receives the parsed learner matrix as ansm and the PRT’s expected property result as expected. This example checker requires exact Gaussian-rational entries: both real and imaginary parts must be integers or fractions, for example 1/2+%i/3. The example XML forbids decimal notation; the checker rejects symbolic or irrational real or imaginary parts such as sqrt(2). These are choices for this example, not restrictions on all matrix inputs or custom checkers. A well-formed matrix that fails the selected property follows its PRT’s false branch. A plain Python True or False can replace the dictionary when no extra feedback is needed.

The complete XML question sets the matrix input’s model answer to <tans>matrix([1,0],[0,1])</tans>, which fixes the editor at \(2\times2\) but does not limit correct responses to the identity. Its PRT passes the expected property result and awards marks:

def positive_multiple(student, teacher):
    if student.is_Integer is not True:
        return {"valid": False, "correct": False,
                "feedback": "Enter an integer value."}
    return bool(student > 0 and student % teacher == 0)

There is no separate source configuration to maintain. sans must directly name an input. tans can be a parsed teacher answer or author value, such as the divisor d; testoptions names one entry in CHECKERS. It is a single case-sensitive ASCII identifier of at most 64 characters, beginning with a letter and followed by letters, digits, or underscores. It is not a file path or a Python expression. Callable and values

Each registered function must be callable with the two positional arguments student and teacher, and finish synchronously. They are parsed values, not raw answer strings. The function receives the submitted answer and whatever teacher value the PRT’s tans selects. This could be an expected Boolean for a property question or a reference matrix for a different task. The API does not pass a context object, question state or separate configuration argument. Scalar expressions are SymPy expressions; matrices are immutable SymPy matrices. Lists and finite sets are distinct ListValue and SetValue objects with ordered .args (a set retains its submitted entries). Equations have two .args; held logic has .operator and .operands; logical constants use SymPy true and false. The collection and logic types and collection_items are available from stack_sympy.checker_api. These values do not promise to retain the learner’s exact written arithmetic form. A custom checker decides its own mathematical domain, within the existing input and parser limits.

Return a Python bool for an ordinary true/false decision, or a dictionary:

{"valid": True, "correct": False, "feedback": "Try another value."}

Both required fields must be Python booleans. Use valid=False for a response outside this checker’s domain: the learner sees an invalid-input diagnostic and the PRT’s false branch does not run. Use valid=True, correct=False for a mathematically wrong response within the domain. feedback is optional plain text of at most 4,096 characters. A checker cannot return a score or an answer note; the PRT branches control those. Exceptions and malformed results are authoring errors, rather than wrong student answers.

For a matrix, a valid result may also include one diagnostic axis:

{"valid": True, "correct": False,
 "assessment": {"columns": ["correct", "dependent"]}}

Choose exactly rows or columns, with one status per submitted vector. Statuses are correct, incorrect, or dependent. They color the editor but do not award marks. A checker may omit the assessment entirely. If several visited PRT nodes supply an assessment for one input, the last one displayed wins. A quiet PRT node suppresses its checker diagnostic and assessment. The result cannot include extra keys, an assessment for an invalid response, or a SymPy Boolean in place of a Python bool.

Test and publish

Run authored tests with the same module you render:

PYTHONPATH=_extensions/stack-sympy python -m stack_sympy.cli test \
  --file questions/python-checker.xml --python-checkers questions/checkers.py

The build checks referenced names, function signatures and model-answer grading on each rendered variant. Add qtests for alternative correct answers, wrong answers, and important PRT branches. Validate answers checks syntax and input rules; the custom predicate runs on Check answer. The page includes the selected Python source so the same checker runs in local tests and the learner’s browser. Keep secrets out of the module, use available Python and SymPy features, and avoid local imports or services that the browser cannot provide. Make checker functions deterministic; do not rely on module state persisting from one check, variant or test to the next. Custom code can perform arbitrary computation, so review it before publishing. The API does not install packages or add new input types. For code that imports questions directly, import_xml(xml_path, python_checkers=module_path) selects the source; call stack_sympy.checkers.preflight(question, variants) before publication to run the same author checks. grade() and run_question_tests() execute the selected predicate on visited PRT nodes.

NoteTechnical limits

A module may register at most 32 named functions in CHECKERS. Its source must be a nonempty UTF-8 file no larger than 64 KiB. Feedback is plain text up to 4,096 characters. Custom execution does not gain a server process or additional package installation; apply a process timeout to local test runs if authored code could take a long time.
