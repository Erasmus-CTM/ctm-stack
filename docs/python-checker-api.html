Python answer tests

Basis questions, matrix conditions and your own checker

A question may have many mathematically correct answers. This guide helps you choose a test for a space or property and shows how ordinary STACK response trees (PRTs) continue to award the marks. The worked questions let you try each choice.

For teachers

Choose the mathematical test

Task Answer test What counts as correct
Give this particular matrix AlgEquiv Corresponding entries are equivalent and dimensions agree.
Give any basis of a matrix’s null, column or row space PythonChecker with a basis function Independent vectors span that space, regardless of the particular basis chosen.
Give a matrix satisfying stated conditions PythonChecker with a property function The submitted matrix has the expected properties; each may earn its own marks.

The basis and matrix-property examples use one supplied checker file. PythonChecker calls the named function; the usual response trees (PRTs) still decide marks and feedback. AlgEquiv is an existing STACK answer-test name. PythonChecker is an addition to this port, so a native Moodle STACK version needs equivalent Maxima checks and may need different matrix-input settings.

Basis questions: use the matrix in the question

If the prompt asks for a basis of \(\ker A\), the PRT compares the learner’s proposed vectors against the original matrix \(A\), not against one precomputed list of basis vectors. Select the basis checker with the space option set to nullspace; use columnspace or rowspace for the other two spaces. The input’s model answer can be generated from \(A\) with the matching author helper. Another independent basis is still correct. For example, if \(A=\begin{pmatrix}1&2&3\\2&4&6\end{pmatrix}\), both the columns of \(\begin{pmatrix}-2&-3\\1&0\\0&1\end{pmatrix}\) and those of \(\begin{pmatrix}-5&-1\\1&-1\\1&1\end{pmatrix}\) span \(\ker A\).

space option for basis Space being checked How learners enter vectors
nullspace Null space of the original \(A\) One vector per column
columnspace Column space of the original \(A\) One vector per column
rowspace Row space of the original \(A\) One vector per row

The basis examples show alternate correct responses and learner-selected column counts. The matrix editor cannot represent an empty basis, so choose a task with a nonzero-dimensional answer space.

After checking a basis, green marks a nonzero vector in the target space when the valid submitted vectors are independent; it can still belong to an incomplete family. Yellow marks a dependent valid family and red marks zero or out-of-space vectors. These colors explain the answer; the PRT awards marks only for the complete basis in the examples. Edits and resizing clear the colors.

Matrix conditions and partial credit

The determinant-one task accepts any integer \(2\times2\) matrix with determinant \(1\) except the identity. Three PRTs give one third of the score each: integer entries, determinant and nonidentity. An entry-by-entry comparison with the model would reject other correct matrices.

property option for matrix_property Expected result supplied in PRT tans Condition
integer_entries true or false Are all entries integers?
determinant An exact rational value such as 1 Does this square matrix have that determinant?
identity true or false Is it the identity matrix?

The PRT’s tans is the expected property result, not the matrix in the prompt. For determinant one it is 1; for nonidentity it is false. The supplied file provides one matrix_property function with these three choices. It also has the positive-definiteness functions below. A question can select any registered function in this file or another author Python file.

Positive definite matrices

A positive definite matrix has a positive quadratic form for every nonzero vector. The full task also requires Hermitian symmetry, which is ordinary symmetry for real matrices. The checker uses Sylvester’s criterion with exact arithmetic, for both real and complex entries.

You can grade the two conditions together or give separate marks for each. The independent positivity check uses the real part of the quadratic form. These four examples show the scoring choices:

Matrix Hermitian (symmetric here)? Positive definite? Combined / separate marks
\(\begin{pmatrix}2&1\\1&2\end{pmatrix}\) Yes Yes \(1\) / \(1\)
\(\begin{pmatrix}2&1\\0&2\end{pmatrix}\) No Yes \(0\) / \(1/2\)
\(\begin{pmatrix}1&2\\2&1\end{pmatrix}\) Yes No \(0\) / \(1/2\)
\(\begin{pmatrix}0&1\\0&0\end{pmatrix}\) No No \(0\) / \(0\)

Use integers or exact fractions for real and imaginary parts; enter %i for \(i\). For example, matrix([2,%i],[-%i,2]) earns full credit.

The first activity uses is_hpd for one overall decision. Its PRT awards full credit when both conditions hold. See the authoring walkthrough for the XML and Quarto block.

Give any real symmetric or complex Hermitian positive definite \(2\times2\) matrix. Use integers or exact fractions for real and imaginary parts; enter %i for \(i\).

PythonChecker API and a scalar example

Use the supplied matrix functions or write your own PythonChecker rule. Save a Python file beside your question materials, register a named function in its CHECKERS dictionary, then give Quarto that filename in #| python-checkers:. Quarto reads the file when it builds the page and includes its source for browser grading; the XML only names the function. The positive-multiple example checks any positive integer multiple of a given number. Its author module contains:

def positive_multiple(student, teacher, options):
    if student.is_Integer is not True:
        return {"valid": False, "correct": False,
                "feedback": "Enter an integer value."}
    return bool(student > 0 and student % teacher == 0)

CHECKERS = {"positive_multiple": positive_multiple}

Both filenames in this block are relative to this .qmd page. For the CLI, filenames are relative to the working directory. There is no separate source configuration to maintain. sans must directly name an input. tans can be a parsed teacher answer or author value, such as the divisor d. testoptions is a JSON object. Its required checker key names one entry in CHECKERS; its optional options key is another JSON object passed to that function. For example, {"checker":"basis","options":{"space":"nullspace"}} selects basis and passes {"space":"nullspace"}. With no options key, the function receives {}, as in {"checker":"positive_multiple"}. An options object can hold several named settings, including nested arrays or objects. For an author-written my_rule, for example, {"checker":"my_rule","options":{"mode":"strict","weights":[1,2]}} passes a Python dictionary with both settings; the function decides what they mean. The checker name is a case-sensitive ASCII identifier of at most 64 characters, beginning with a letter and followed by letters, digits or underscores. Options are JSON values, not CAS or Python expressions; they are not interpolated with author variables. The selected module is author code packaged with the page; use only code you trust and expect learners to be able to see in a published site.

Callable and values

Each registered function must be callable with the three positional arguments student, teacher and options, and finish synchronously. The first two are parsed values, not raw answer strings: the learner’s submitted answer and whatever teacher value the PRT’s tans selects. This could be an expected Boolean for a property question or the original matrix for a basis question. options is the parsed JSON object described above. The API does not pass a context object or question state. Scalar expressions are SymPy expressions; matrices are immutable SymPy matrices. Lists and finite sets are distinct ListValue and SetValue objects with ordered .args (a set retains its submitted entries). Equations have two .args; held logic has .operator and .operands; logical constants use SymPy true and false. The collection and logic types and collection_items are available from ctm_checkers.stack.checker_api. These values do not promise to retain the learner’s exact written arithmetic form. A custom checker decides its own mathematical domain, within the existing input and parser limits.

Return a Python bool for an ordinary true/false decision, or a dictionary:

{"valid": True, "correct": False, "feedback": "Try another value."}

Both required fields must be Python booleans. Use valid=False for a response outside this checker’s domain: the learner sees an invalid-input diagnostic and the PRT’s false branch does not run. Use valid=True, correct=False for a mathematically wrong response within the domain. feedback is optional plain text of at most 4,096 characters. A checker cannot return a score or an answer note; the PRT branches control those. Exceptions and malformed results are authoring errors, rather than wrong student answers.

For a matrix, a valid result may also include one diagnostic axis:

{"valid": True, "correct": False,
 "assessment": {"columns": ["correct", "dependent"]}}

Choose exactly rows or columns, with one status per submitted vector. Statuses are correct, incorrect, or dependent. They color the editor but do not award marks. A checker may omit the assessment entirely. If several visited PRT nodes supply an assessment for one input, the last one displayed wins. A quiet PRT node suppresses its checker diagnostic and assessment. The result cannot include extra keys, an assessment for an invalid response, or a SymPy Boolean in place of a Python bool.

Test and publish

Run authored tests with the same module you render:

export PYTHONPATH=$(ls _extensions/ctm-checkers/*.whl | paste -sd: -)  # ctm-checkers' two wheels
python -m ctm_checkers.stack.cli test \
  --file questions/python-checker.xml --python-checkers questions/checkers.py

The build checks referenced names, function signatures and model-answer grading on each rendered variant. Add qtests for alternative correct answers, wrong answers, and important PRT branches. Validate answers checks syntax and input rules; the custom predicate runs on Check answer. The page includes the selected Python source so the same checker runs in local tests and the learner’s browser. Keep secrets out of the module, use available Python and SymPy features, and avoid local imports or services that the browser cannot provide. Make checker functions deterministic; do not rely on module state persisting from one check, variant or test to the next. Custom code can perform arbitrary computation, so review it before publishing. The API does not install packages or add new input types. For code that imports questions directly, import_xml(xml_path, python_checkers=module_path) selects the source; call ctm_checkers.stack.checkers.preflight(question, variants) before publication to run the same author checks. grade() and run_question_tests() execute the selected predicate on visited PRT nodes.

NoteTechnical limits

A module may register at most 32 named functions in CHECKERS. Its source must be a nonempty UTF-8 file no larger than 64 KiB. Feedback is plain text up to 4,096 characters. Custom execution does not gain a server process or additional package installation; apply a process timeout to local test runs if authored code could take a long time.
