Python answer tests and custom checkers

Your answers are saved only in this browser.

Use a Python checker when the task accepts a mathematical property rather than one displayed answer. Install CTM Assessment and use filters: [ctm-assessment]; the shared checker library supplies Python and SymPy. Checker source is trusted author code and is public in the static page. Keep credentials and private data out of it.

Choose the mathematical test

Use the XML’s ordinary answer tests for equivalence, written form and numeric tolerance. For matrix properties, PythonChecker nodes can select these predicates from ctm_checkers.matrix:

Name Options What the node checks
basis space: nullspace, columnspace or rowspace A basis for the space of the matrix in <tans>
matrix_property property: integer_entries, determinant or identity The indicated property equals <tans>
is_hermitian None Hermitian symmetry equals the boolean <tans>
is_positive_definite None Positivity of the Hermitian part equals <tans>
is_hpd None Hermitian symmetry and positive definiteness together

For example, a basis node uses:

<answertest>PythonChecker</answertest>
<sans>ans</sans>
<tans>A</tans>
<testoptions>{"checker":"basis","options":{"space":"nullspace"}}</testoptions>

A is the defining matrix, not a displayed basis. The basis predicate accepts any independent family that spans the required space. It reports green, red and dependent-vector assessments without preferring an ordering. Library predicates keep their exact rational-domain and matrix-size restrictions. A question using them needs no checker filename or block checker:.

Symmetric positive definite matrices

For a real matrix, is_hpd requires symmetry and positive definiteness. For a complex matrix, it requires Hermitian symmetry and positive definiteness. The library checks every leading principal minor; a positive determinant alone is insufficient. Use integers or exact fractions for real and imaginary parts and %i for the imaginary unit.

Give any real symmetric or complex Hermitian positive definite \(2\times2\) matrix. Use integers or exact fractions for real and imaginary parts; enter %i for \(i\).

PythonChecker API and a scalar example

Write a block checker: with check(response, symbols). The same function contract works in math-exercise when its field labels equal the STACK input names. This example accepts any positive integer multiple of the displayed number:

Enter any positive integer multiple of \(2\).

Show source
```{.stack-question #docs-custom-multiple}
#| label: docs-custom-multiple
#| variants: 3
#| file: ../questions/python-checker.xml
#| question: A positive integer multiple (PythonChecker)
#| checker: |
#|   def check(response, symbols):
#|       answer = response["answers"]["ans"]
#|       divisor = response["variables"]["d"]
#|       if answer.is_Integer is not True:
#|           return {"valid": False, "feedback": "Enter an integer value."}
#|       correct = answer > 0 and answer % divisor == 0
#|       return {"correct": bool(correct),
#|               "feedback": "" if correct else "Use a positive integer multiple of the given number."}
#| tests:
#|   - name: displayed multiple
#|     answers: {ans: d}
#|     expect: correct
#|   - name: wrong offset
#|     answers: {ans: d+1}
#|     expect: wrong
#|   - name: fractional input
#|     answers: {ans: 'raw("1/2")'}
#|     expect: invalid
#| review: true
```

The XML node uses {"checker":"check"}. It adds its own evaluated values as response["node"] = {"sans": ..., "tans": ..., "options": ...}. options is the literal JSON object inside testoptions, never evaluated as CAS or Python. A partial checker result takes the node’s false branch; the node’s normal branch scores still determine that XML tree’s score.

Response and result

The checker receives these values after the selected backend has validated all inputs:

Key Value
kind "expressions"
raw Student strings in XML input order
expressions Parsed values in the same order
answers Parsed values keyed by XML input name
teacher Teacher values keyed by XML input name
variables Exact question variables
inputs Named input descriptions, including raw and canonical
variant {n, id, hash}; an unapproved candidate has no published number
node Present only during a PythonChecker node call

Matrix input descriptions also carry rows, cols, flattened expressions and a SymPy matrix. symbols maps free symbol names to their SymPy symbols, with the question’s assumptions. The checker namespace contains the shared math-exercise helpers, including SymPy names and assess_basis.

Return True or False, a number between 0 and 1, or a dictionary containing score or correct. Optional keys are feedback, show_score and assessment. Feedback is plain text. A matrix assessment names the input:

return {"score": 0.5, "feedback": "Review the dependent columns.",
        "assessment": {"ans": {"columns": ["correct", "dependent"]}}}

Each assessment list must match the submitted row or column count. A result such as {"valid": False, "feedback": "Enter an integer value."} rejects the attempt without a score. Invalid attempts clear vector assessments. A checker that raises, returns a malformed result or cannot decode a required author value is an author error; it does not count as a wrong learner answer. Each invocation gets a fresh namespace.

Score and placement

A block checker creates an implicit response tree named checker, with checker-value: 1 by default. Its normalized score counts alongside the XML trees:

\[ \text{score}=\frac{\sum_{\text{trees}}\text{value}\times\text{score}} {\sum_{\text{trees}}\text{value}}. \]

For XML tree scores 1 and 0, both of weight 1, and a checker score 0.5 with checker-value: 2, the question scores 0.5. With no XML trees, the checker supplies the whole grade. Use [[feedback:checker]] in CASText to place its feedback. Penalties and score rounding follow the same rules as XML trees. The name checker is reserved when the block defines a checker.

The XML node and the implicit checker are separate evaluations. A node calls the function as a predicate and supplies response["node"]; the implicit checker call has no node key and contributes its numeric score. Write the function to support both contexts when the XML calls it.

Test and publish

Run XML and declarative question tests for every variant, inspect the student previews, and approve the variants before publishing. Review mode permits proposals for teacher inspection; it does not approve them. Normal publishing requires current approved variants.

The old python-checkers: filename, CHECKERS registry and ctm_checkers.stack.checker_api module have been removed. Move custom logic into checker: and change its arguments to response, symbols. Supplied matrix predicates now come from the shared library without a filename. The SymPy backend implements this contract now. Maxima’s future continuation will call the same checker with validated written values.
