STACK compliance

Expected behavior, engine agreement, and known limitations

Each source case compares a submitted answer with a reference using a named STACK answer test. The SymPy port implements a subset of STACK; this page shows its coverage gaps, expected behavior, and agreement with STACK and the browser.

Port is this SymPy implementation. STACK is the reference Maxima implementation. Expected is the source fixture’s intended accept, reject, or error result. Only STACK tests with a fully supported equivalent in the Python port were run.

Semantics and open questions explains the implemented conventions and the remaining case-specific questions for discussion with STACK. Recorded domain differences and unproved identities remain visible and individually pinned; browser agreement does not resolve them.

Scope and technical details

This compares CAS answer-test functions rather than complete Moodle grading sessions. The port currently provides nine answer-test families, including flat finite scalar lists/sets with AlgEquiv and Sets. Cases outside port coverage stay in the inventory and are labeled by the missing answer test or unsupported input/feature. Some direct reference calls are also omitted because they need parser or controller preparation.

“Test applicability” asks whether an answer test can compare the supplied values. It is separate from input syntax validity and from the final accept/reject mark. Form tests such as EqualComAss can reject mathematically equivalent expressions.

Source codes 0 and 1 mean expected rejection and acceptance; -1 expects a controlled error. Codes -2 and -3 flag source-authored native deviations. Only specifically reviewed cases are labeled “Known STACK issue.” Ordinary feedback notes are retained but not generally compared; asserted controlled-error notes are checked separately.

Browser agreement includes input/scope classifications as well as graded results. The summary separates these. STACK coverage counts available observations, not compatibility passes.
